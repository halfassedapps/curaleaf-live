# Curaleaf Live (phone page)

Goal: publish `index.html` on GitHub Pages so Jeff can open it on his iPhone and use Share > Add to Home Screen.

## What the page is
- One self-contained static HTML file, no build step, no server. Everything runs in the browser.
- On open it calls Curaleaf's Sweed API directly (CORS is open; verified from a foreign origin):
  `POST https://web-ui-curaleaf.sweedpos.com/_api/proxy/Products/GetProductList` and `.../Products/GetExtendedLabdata`, header `storeid: 153` (Harrisburg PA).
- Store picker covers the 18 PA stores (Sweed store IDs 145-162; 144 "Curaleaf PA" is a dead duplicate with no menu). Choice saved in localStorage `curaleafLive.store`, default 153. Flower category 1287 is the same at every PA store. Store list came from `Store/GetStoreInfo` (header `storeid`), which returns name, address, and the curaleaf.com `url` slug.
- Caches the result in localStorage (`curaleafLive.v1`, plus `.<storeid>` suffix for non-Harrisburg stores) for 6 hours; Refresh button clears it.
- Phone layout (<=640px): each product is a card; sort dropdown + collapsed filters. Verified at 390px in desktop Chromium with a mocked API, NOT yet on a real iPhone and NOT yet against the live API from a hosted origin.
- "Added" date: Curaleaf's API has no add date (checked: only promo start/end fields). Dates come from our own daily snapshots (first seen), one file per store: `data/firstseen-<storeid>.json` with `base` (tracking start), `known` (on the menu at base, shown "by <base>"), `first` (key -> date). Key is `brand||name productType`. Harrisburg tracking began 2026-10-11; other stores begin on their first Action run. The page fetches the chosen store's file; the embedded `var FS=` (Harrisburg, 2026-10-26) is only a fallback if that fetch fails. Products not in the file get today's date + "(seen)", stored per device in localStorage (`curaleafLive.seen`, `.<storeid>` suffix for other stores).
- Daily tracking runs in GitHub Actions (`.github/workflows/track.yml` -> `scripts/track.py`, ~9am ET, also runnable manually), committing changes to `data/`. A store whose menu can't be fetched completely is skipped that day.
- Prices shown include the first-visit 45% promo: min(promo or list, 0.55*list).

## Tasks
1. `git init`, add `index.html` (and optionally this file), commit, create a PUBLIC GitHub repo (e.g. `curaleaf-live`) with `gh repo create --public --source=. --push`.
2. Enable Pages: repo Settings > Pages > Deploy from branch `main`, folder `/ (root)`. (Or `gh api -X POST repos/OWNER/REPO/pages -f 'source[branch]=main' -f 'source[path]=/'`.)
3. Open `https://OWNER.github.io/REPO/` in a desktop browser, confirm the table loads (DevTools console: no CORS/fetch errors). If the browser blocks the API, tell Jeff; don't work around it.
4. Give Jeff the URL and the iPhone step: Safari > Share > Add to Home Screen.
